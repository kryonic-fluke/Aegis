Why Two-Tier Caching?

Redis Exact Cache (Tier 1): Evaluates in 2.11 ms with zero embedding cost. Absorbs 60–70% of high-frequency repeated queries at 1,417+ req/s.

PostgreSQL pgvector (Tier 2): Matches semantically equivalent prompts (20–25% of traffic) in 678 ms vs. 9,110 ms cold upstream, yielding a 92.55% latency reduction.

Backfill Mechanics: When a semantic hit resolves, Aegis writes that specific paraphrase to Redis exact cache. Next time, it resolves in 2.1 ms (322x speedup).

Distributed Rate Limiting via Lua

The Problem: In distributed systems, separate read-modify-write calls create race conditions (Check-Then-Act anti-pattern) under multi-replica deployments.

The Solution: Atomic Redis Lua scripts calculate token replenishment and capacity consumption in a single atomic transaction without distributed locks.

Empirically Verified: Sustained 154,378 burst requests at 7,525.8 req/s with zero 5xx server crashes and 2.07 ms rejection latency.

The Semantic Cache Bottleneck

In our benchmarks, we instrumented separate headers for local vector search vs. cloud embedding:

  • Local pgvector HNSW search: 1.01 ms
  • Google Gemini Embedding API: 684.54 ms

Takeaway: pgvector is not the bottleneck (accounting for <0.2% of retrieval). 99.8% of time is the external network hop. In production, hosting an in-cluster embedding container (ONNX / TEI) drops semantic retrieval under 15 ms.

Realistic Mixed Traffic (70/20/10)

When tested under real-world Pareto traffic (64% exact hits, 25% semantic hits, 11% cold misses):

  • Total Cache Hit Ratio: 89.01%
  • Token / Cost Savings: ~89%
  • Blended Median (P50) Latency: 1.57 ms

Even when 11% of requests take 9–18s upstream, half of all users experience 1.57 ms speed because 89% of calls are absorbed by the multi-tier cache.
